What this is

The cheapest place in the whole lifecycle to catch a problem, because nothing has moved yet. The common gates run first: identity, authority, catalogue, folio. Then the flow splits, and it splits properly rather than into one long gate chain, because the money-in checks and the money-out checks have almost nothing in common. One asks whether funding exists and whether the rail can carry the ticket. The other asks whether the units exist, are free, and are past their lock-in.

What is deliberately not here

Mandate registration and authentication. The boundary on record is that anything registered now to debit later belongs to the Mandate journey, and paying immediately belongs to the Order journey. So this diagram shows the attachment contract and nothing more.

Drawing standard

Fixed across the series. Five of these are checked when the diagram is built, and the file is not written if any check fails.

  • Orthogonal only. Every connector segment is exactly horizontal or vertical. No diagonals. Checked.
  • Turns at the midpoint. Where a connector needs two turns, the crossing run sits at the exact midpoint of the span, so both legs are equal.
  • Edge attachment, separated. Connectors leave and enter only on a shape's edge, never at a corner and never inside it. Where several arrows meet the same shape they attach at different points along that edge rather than stacking on the midpoint, so each stays traceable. On a decision diamond that means a point along the relevant slanted face.
  • No connector crosses a shape. Checked.
  • Every arrowhead lands on a shape outline. Never in empty space. This matters most on a decision diamond, whose bounding box is not its outline, so a point that looks like the top edge floats clear of the shape. Checked.
  • No two arrowheads coincide. Same-colour heads must also stand clear of each other. Checked.
  • Phase bands occupy clear strips. A band is placed only in a horizontal strip containing no shape at all, so a band label can never collide with a box. Placement is computed, not eyeballed. Checked.
  • Colour carries meaning. Purple is the main path, amber is remediation, red is a blocking failure, teal is a shortcut or handoff.
  • Room over compactness. Height is unconstrained, so type stays large and nothing is crowded.

The flow

Where this sits in the Order set

O1 Placement and pre-flight · O2 Execution, pricing and settlement · O3 Failure, rejection and reversal · O4 Systematic plans · O5 Switch and STP. One order spine with typed gates, plus the three things that refuse to sit on it: a plan is not its instalments, a switch is two orders with a dependency, and Failed and Reversed are separated by the allotment line. Mandate registration and authentication are deliberately absent throughout: anything registered now to debit later belongs to the Mandate journey, and these diagrams show only the attachment contract.

Two gates worth arguing about

KYC first, always. There is deliberately no captured-but-not-yet-placed state in the V1 order model, so an eager investor cannot park an order against a pending KYC. That is a recorded decision, not an oversight, and taking it up later means adding a pre-placement draft state to the order model rather than relaxing a check.

The folio gate is a four-way match, not a lookup. Reuse only when investor, fund house, holding mode and repatriability class all match; if any one differs, a separate folio is correct and intentional. And for a new investor at a fund house there is no folio to find: the first purchase carries the create instruction and the folio comes back with the units, which is why this is drawn as a gate on reuse rather than a create-account step.

Grounded against, and what is open

The Order reference for the pre-flight failure catalogue and the transaction family; the Investor and Instrument references for the gates each reads. The register at v0.17 for D39 on KYC-first, D38 and D42 on folio creation and reuse, D5 on cut-offs as fetched parameters, D15 on the payment rail for a high-value SIF entry, D43 on mandate attachment, D44 on the Order and Mandate boundary, and D45 on non-resident disclosure before confirmation. Two gates rest on unfinished matter, and the two are not the same kind. D28 is still open in the register: the scope ruling that V1 builds an encumbrance check is made, but the pledge and lien feed mechanics are parked until pledging enters scope, so the encumbrance gate is drawn as a check whose source is not yet settled. D31 is closed, with a named follow-up: the per-bank effective limits are held open by design until Mandate PRD time, so the rail-ceiling gate knows the headline numbers but not the bank-level ones that will bite in practice. The gate itself is settled; only its values are outstanding.
