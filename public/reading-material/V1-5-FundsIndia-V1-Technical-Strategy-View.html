This view is deliberately a different lens from the Big-Block Map v2. The Map is build-sequence and strategic; this is component-and-altitude. The organising question here is not "what do we build when" but "what is a domain home, what is an adapter behind an ACL, what is a read layer, what is cross-cutting, and what is just a pipe." Everything is drawn purely through the MFD distributor lens: the platform never touches client money, the ledger is a reconciliation projection of RTA truth, and recommendation-shaped surfaces stay inside dissection-not-prescription bounds.

Domain HomesBounded contexts · system of engagement
Each owns its entity, lifecycle, and invariants. These are the blocks that own state and emit domain events onto the spine. The ledger is a projection of RTA truth, not the system of record.
Identity
Social + phone/OTP login; KYC for Resident, Minor, NRI/OCI. Owns the investor identity and KYC status ladder.

Consent & Authorization

Rail ACLs & Integration AdaptersAnti-corruption layer · system of record = external
Every external rail sits behind its own ACL written to a vendor-neutral domain interface. Rail-agnostic architecture behind a proper ACL is sacrosanct: vendor change must never bleed into a domain home. One ACL per domain even where a single vendor spans two.
Execution Rail ACL
Transaction execution abstracted via Fintech Primitives (FP) in V1; BSE StAR MF as V1.5 fast-follow; PG (Razorpay) on the FP-RTA gateway path.
Rail ACL
Account Aggregator Rail ACL
Finvu as live AA in V1, behind a vendor-neutral interface. Feeds financial-picture (J13). Multi-AA gateway (Finarkein/Setu) is a V1.5 upgrade.
Rail ACL→ seam for multi-AA gateway
Identity Rail ACL
HyperVerge (identity), KRA/CKYC at CERSAI, UIDAI. Feeds the Identity domain; abstracted so the rail can change beneath KYC.
Rail ACL
Legacy CRM Sync
Outbound integration edge. Ingests V1 domain info into the legacy CRM. An ACL, not a relationships concern.
Rail ACL
Pipe · not a block
Domain Event Spine
Typed, bitemporal Kafka stream carrying domain events between bounded contexts. The operational backbone every home publishes to and subscribes from. It is a connector, drawn here as a pipe rather than a node. Clickstream is kept permanently separate from this spine.
Analytical SinkDownstream consumer
Reads off the spine and clickstream; emits nothing back into the domains. A destination, not a participant.
Data Lake
Analytical sink. Consumes domain events + clickstream (the two kept separate). Downstream of the spine; never writes back into domain homes.
Sink
Cross-Cutting CapabilitiesWraps every layer · not nodes
Crypto / PII / DPDP
KMS, tokenization vault for Aadhaar/PAN, data residency, DPDP erasure. Tiered: AA-pulled financial data is heavier than KYC fields. A capability, not a block.
Audit & Attribution
A property of the bitemporal ledger + spine, plus ARN/EUIN attribution integrity in the Order path and a recommendation-surface audit trail for MFD provability.
